# Voice Notes MVP

FastAPI 하나로 실행하는 **한국어·영어 혼합 강의 전사·학습 노트** 앱입니다. 영어 전문 용어를 원문 표기로 유지하며 요약은 한국어로 작성합니다. 프런트엔드는 HTML/CSS/JavaScript이며 Node, npm, 프런트엔드 빌드가 필요 없습니다.

- 실시간 전사: Soniox `stt-rt-v5`, `language_hints: ["ko", "en"]`, `language_hints_strict: true`
- 과목별 설정: 강의 배경(context)과 전문 용어(terms)를 UI에서 입력하고 브라우저에 저장
- 실시간 노트: 확정 원문의 `<end>`마다 청크를 만들어 선택한 OpenAI 모델에 전송(기본 `gpt-6-luna`), 직전 두 청크를 문맥으로 제공
- 실시간 요약 노트: 각 청크의 **핵심 주제 제목**과 **새 내용 / 반복된 내용 / 보완·정정**을 스트리밍 표시하고, **이 요약의 전사 원문**을 펼쳐 해당 청크의 발화를 확인
- 최종 노트: 종료 후 전체 확정 원문을 선택한 모델로 요약(기본 `gpt-6.1-sol`)
- 왼쪽 **과목 · 노트**: 과목 폴더 아래에 녹음별 전사 원문·실시간 요약·최종 노트를 SQLite에 저장
- 과목 종합 노트: 해당 과목의 강의 최종 요약들을 통합해 과목마다 하나의 노트로 관리
- 강의 노트 이동·삭제, 과목 종합 노트 삭제, 빈 과목 폴더 삭제
- 원문·완료된 실시간 요약·최종 노트 Markdown 다운로드, 최종 노트 실패 시 다시 시도

최종 노트는 강의 개요, 핵심 개념·정의, 설명·구체적 예시, 복습 포인트, 확인이 필요한 내용으로 구성됩니다. 영어 전문 용어와 약어는 억지로 번역하거나 한글로 음차하지 않도록 지시합니다. 번역 API는 요청하지 않습니다.

## 실행

Python 3.11 이상과 Soniox/OpenAI API 키가 필요합니다. API 사용료는 각 계정에 청구됩니다.

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

`.env`에 키를 입력합니다. 이미 `.env`가 있으면 복사하지 말고 해당 파일을 수정하세요.

```dotenv
SONIOX_API_KEY=본인의_Soniox_API_키
OPENAI_API_KEY=본인의_OpenAI_API_키
OPENAI_REALTIME_MODEL=gpt-6-luna
OPENAI_FINAL_MODEL=gpt-6.1-sol
```

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# .env에 API 키 입력
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

[http://localhost:8000](http://localhost:8000)을 최신 Chrome 또는 Edge에서 열고, **과목 설정 → 녹음 시작 → 마이크 허용 → 종료 및 요약** 순서로 사용합니다. 한국어·영어 원문과 청크별 실시간 요약 노트, 최종 노트가 표시됩니다. **기록 다운로드**로 확정된 원문과 완료된 노트를 저장합니다. 시작 버튼이 비활성화되어 있으면 `.env`를 확인하고 서버를 재시작하세요. `.env` 변경은 자동 재시작 대상이 아닙니다. 운영체제 환경 변수는 `.env`보다 우선합니다.

## 휴대폰 접속 (ngrok)

PC에 [ngrok](https://ngrok.com/download)을 설치한 뒤 [본인 계정의 authtoken](https://dashboard.ngrok.com/get-started/your-authtoken)을 `.env`에 추가합니다. 이미 `ngrok config add-authtoken`으로 등록했다면 기존 ngrok 설정을 사용합니다.

```dotenv
NGROK_AUTHTOKEN=본인의_ngrok_authtoken
# 선택: 계정에 지정된 ngrok HTTPS 주소
NGROK_URL=
# 선택: 공백·$를 제외한 영문/숫자/기호 8~128자. 비우면 실행 시 자동 생성
MOBILE_PASSWORD=
```

### uvicorn과 ngrok을 각각 실행

`.env`의 `ALLOWED_HOSTS`에 본인의 ngrok 호스트명을 추가하고 uvicorn을 시작합니다. 이미 서버가 켜져 있다면 설정 적용을 위해 한 번 재시작합니다.

```dotenv
ALLOWED_HOSTS=localhost,127.0.0.1,[::1],example.ngrok-free.dev
```

터미널 1에서 앱을 실행합니다.

```bash
uv run uvicorn main:app --host 127.0.0.1 --port 8080 --proxy-headers --forwarded-allow-ips 127.0.0.1
```

터미널 2에서 ngrok을 실행합니다. `example.ngrok-free.dev`는 본인 주소로 바꿉니다. ngrok CLI는 프로젝트의 `.env`를 자동으로 읽지 않으므로 처음에는 `ngrok config add-authtoken`으로 토큰을 등록하거나 터미널 환경 변수로 설정해야 합니다.

```bash
ngrok http 8080 --url https://example.ngrok-free.dev
```

두 프로세스를 함께 켜 두면 같은 서버를 PC와 휴대폰에서 사용할 수 있습니다. ngrok만 종료하면 PC 서버는 계속 실행됩니다. 위의 ngrok 직접 실행 명령에는 아래 실행기의 접속 비밀번호 정책이 적용되지 않습니다. 이 방식에서는 `run_mobile.py`를 추가로 실행하지 않습니다.

### 앱과 ngrok을 함께 실행

기존 8000번 서버를 종료한 뒤 아래 명령 **하나로 앱과 ngrok을 함께 실행**합니다. 추가 Python 패키지는 필요 없습니다.

```powershell
# Windows PowerShell
.\.venv\Scripts\python.exe run_mobile.py
```

```bash
# macOS / Linux / WSL (ngrok도 같은 환경에 설치)
.venv/bin/python run_mobile.py
```

1. 터미널에 출력된 **휴대폰 접속: https://…** 주소를 휴대폰 브라우저에서 엽니다. 같은 Wi-Fi에 연결할 필요는 없으며 PC와 휴대폰 모두 인터넷에 연결되어 있어야 합니다.
2. 접속 인증 창에서 아이디 **voice**, 터미널의 **접속 비밀번호**를 입력합니다. ngrok의 방문 확인 화면이 나타나면 **Visit Site**를 눌러 진행합니다.
3. 앱에서 **녹음 시작**을 누르고 휴대폰 마이크 권한을 허용합니다. 녹음 중에는 브라우저를 화면에 유지하세요. PC의 동일한 SQLite 노트를 조회·저장합니다.
4. PC 터미널에서 **Ctrl+C**를 누르면 앱과 ngrok을 함께 종료합니다. 코드나 `.env` 변경 후에도 다시 실행합니다.

`--port 8001`로 포트를 변경할 수 있습니다. ngrok을 찾지 못하면 터미널을 다시 열거나 `.env`의 `NGROK_BIN`에 ngrok 실행 파일 경로를 지정합니다. 연결 오류에 `ERR_NGROK_…`가 표시되면 [ngrok 오류 코드 문서](https://ngrok.com/docs/errors)에서 확인합니다.

실행기는 사용할 로컬 포트를 먼저 확보한 뒤 HTTPS 주소를 만들고, 그 주소만 서버의 허용 호스트에 추가합니다. 전달 헤더는 로컬 ngrok 연결만 신뢰하며 기존 Origin 검사를 유지합니다. HTTP 요청과 WebSocket 연결은 ngrok의 [Basic Auth 정책](https://ngrok.com/docs/gateway/traffic-policy/actions/basic-auth)으로 보호하고, ngrok의 로컬 HTTP 내용 검사는 끕니다. 원래 `uvicorn` 명령으로 로컬에서만 실행하는 방식도 계속 사용할 수 있습니다. ngrok은 [HTTPS와 WebSocket 전달을 지원합니다](https://ngrok.com/docs/gateway/endpoints/http).

## 과목별 설정

- 과목명: 예를 들어 `일반물리학`. 최대 80자이며 Soniox `context.general`의 `topic`으로 전달합니다.
- 강의 배경·설명: 예를 들어 `뉴턴 역학 수업. 운동량, 힘, 에너지 보존을 다루며 영어 전문 용어가 섞입니다.` 최대 2,000자이며 `context.text`로 전달합니다.
- 인식할 용어: `momentum`, `각운동량`, `Hamiltonian` 등을 **한 줄에 하나씩** 입력합니다. 최대 100개, 각 80자이며 공백·빈 줄·중복을 정리한 뒤 `context.terms`로 전달합니다.
- 앱에서는 context 요청 JSON을 UTF-8 8,000바이트 이하로 제한합니다. 너무 긴 설명이나 용어 목록은 시작 전에 줄여 주세요.
- **전사 설정 저장** 후 선택 목록에서 다시 불러올 수 있습니다. 같은 과목명으로 저장하면 덮어쓰며 최대 50개를 보관합니다. 과목명을 바꿔 저장하면 다른 설정으로 추가합니다. **전사 설정 삭제**는 설정 목록만 지우며 저장된 강의나 과목 폴더를 삭제하지 않습니다.
- 저장 위치는 현재 브라우저의 `localStorage`입니다. 저장소를 사용할 수 없어도 현재 입력으로 녹음할 수 있습니다. 다른 브라우저나 기기에 동기화하지 않습니다.
- 저장 버튼을 누르지 않아도 현재 입력값으로 녹음합니다. 비워 두면 기본 전사 설정을 사용합니다. 녹음·요약 중에는 설정을 잠가 세션 중간에 바뀌지 않게 합니다.

## 저장된 노트

- 왼쪽 **과목 · 노트**의 과목 폴더에서 녹음별 기록을 선택합니다. 과목명, 녹음 시각, 청크 수와 최종 노트 완료 여부를 표시합니다. 선택하면 **전사 원문 / 청크별 실시간 요약 / 최종 노트**를 모두 복원합니다.
- **새 노트** 또는 **새 녹음**으로 다음 강의를 시작해도 이전 기록은 유지됩니다. 녹음·요약·불러오기 중에는 노트 전환을 잠급니다. 좁은 화면에서는 목록이 상단에 표시됩니다.
- 서버의 `data/notes.sqlite3`에 저장합니다. 처음 조회하거나 녹음할 때 자동 생성하며, SQLite는 Python 기본 라이브러리이므로 별도 설치가 필요 없습니다. 같은 프로젝트 폴더로 서버를 다시 실행하면 그대로 읽습니다. 브라우저 저장소를 비우거나 다른 브라우저를 사용해도 노트 내용은 남습니다.
- 녹음 시 사용한 과목명·context·terms, 녹음 시각·시간도 함께 보관합니다. 과목 설정 목록과 마지막 선택한 노트 ID만 브라우저에 저장합니다.
- 확정 전사가 들어오면 최대 초당 한 번 원문을 저장하고, 청크 요약 완료·전사 종료·최종 요약 완료·연결 종료 시 추가 저장합니다. 목록 API는 원문 전체 대신 메타데이터만 가져오고, 선택한 노트의 본문을 따로 읽습니다.
- 실패하거나 중단된 청크는 **요약 미완료**로 남습니다. 미확정 전사와 생성 중인 요약 조각을 완료된 결과로 저장하지 않습니다. 최종 노트가 미완료면 저장된 원문으로 다시 시도하며, 화면이 더 최신이면 최신 원문과 완료된 청크 요약을 먼저 저장합니다. 재시도 결과는 같은 노트를 갱신합니다.
- DB 저장에 실패하면 왼쪽 아래에 오류를 표시합니다. 화면의 기록은 **기록 다운로드**로 보관할 수 있습니다. 최종 노트가 미완료인 경우 저장 공간·권한 문제를 해결한 뒤 최종 요약을 다시 시도하면 아직 저장되지 않은 노트도 복구해 저장합니다.
- 백업하려면 서버를 종료한 뒤 `data/notes.sqlite3`를 복사하세요. 원본 음성은 저장하지 않습니다. DB 파일은 Git 추적 대상에서 제외합니다.

## 과목 폴더와 종합 노트

1. 왼쪽의 **새 과목명 → ＋ 과목 폴더**로 과목을 만듭니다. 과목 안의 **과목 종합 노트 → 이 과목에 새 강의**로 녹음을 준비하면 과목명이 채워집니다.
2. 녹음 결과는 입력한 과목명의 폴더에 쌓입니다. 같은 이름의 폴더가 없으면 자동 생성합니다. 기존 강의도 저장된 과목명으로 분류하며, 과목명이 없는 강의는 **미분류**에 둡니다.
3. 강의 노트 상단의 **저장 과목** 선택 상자로 다른 폴더 또는 미분류로 이동할 수 있습니다. 이동해도 원문·실시간 요약·최종 노트와 녹음 당시 전사 설정은 보존합니다.
4. 과목의 **종합 노트 생성 / 종합 노트 갱신**을 누르면 그 과목에서 **완료된 강의 최종 요약만** 모아 다시 요약합니다. 전사 원문과 실시간 요약, 다른 과목의 자료, 미완성 최종 요약은 입력에 포함하지 않습니다.
5. 종합 노트는 추적 기능을 넣기 전과 동일하게 주제별 핵심 개념과 연결 관계, 정의·공식·예시, 보완·정정 및 상충 내용, 복습 포인트를 자연어로 통합합니다. 중복 설명을 합치고 새로운 내용을 보존하며, 자료가 길면 여러 묶음으로 요약한 뒤 다시 통합합니다.
6. 완성된 본문을 고정한 다음 **별도 API 요청으로 출처와 기존 ID의 대응 관계만** 붙입니다. 본문 생성에는 ID·추적 형식·이전 추적 문서를 넣지 않습니다. 추적 응답에는 본문·제목 수정 필드가 없으며, 서버가 원래 본문에서 문단과 위치를 복사합니다. 본문과 추적 정보는 모두 성공해야 함께 저장되고, 실패하면 이전 노트를 유지합니다.

종합 노트는 **파트 `P0001` → 내용 `N0001` → 변경 기록 `U0001`**로 추적합니다. ID는 과목 안에서 서버가 발급합니다. 이전 내용과 대응하는 항목은 ID·최초 추가 시각을 유지하며 변경된 본문과 출처를 이력으로 남깁니다. 신규 내용에만 새 ID를 붙이고, 완전히 동일한 문단은 추적 응답이 ID를 누락해도 서버에서 일대일로 기존 ID를 복구합니다. 요약 흐름에 따라 파트 제목·위치가 달라지면 그 변경도 기록합니다. 추적 단계에만 이전 항목 정보를 전달하고 누적 변경 이력 전체는 모델에 보내지 않습니다.

화면은 생성된 본문을 원래 순서대로 보여주고, 각 구간 아래에 출처·추가 시각·변경 이력을 접어 둡니다. Markdown도 원래 본문 뒤에 구절별 ID·출처·시각과 변경 이력을 붙입니다. 종합 본문은 기존과 같이 추론 `low`, 출력 상한 6,000토큰으로 생성하며, 추적 정보는 별도 구조화 응답(최대 16,000토큰)으로 받습니다. 일반적인 갱신은 요약 1회와 추적 1회이며, 자료가 많으면 각각 묶음으로 처리하므로 API 호출이 추가됩니다. 전체 갱신은 최대 10분이고, 기존 강의 최종 노트·실시간 요약 설정은 유지합니다.

각 구간의 **출처·이력**을 펼치면 강의 제목·녹음 시각·강의 ID·최종 요약의 근거 문장을 볼 수 있고 강의를 눌러 원문과 최종 노트로 이동할 수 있습니다. 강의 ID와 인용문을 입력 강의와 대조하며, 해당 최종 요약의 SHA-256을 보관해 이후 재요약 여부를 구분합니다. 직접적인 근거를 찾지 못한 문장은 본문을 바꾸지 않고 **직접 근거 미확인**으로 표시합니다. 최초 추가·최근 반영 시각은 서버가 기록하고 화면은 브라우저 현지 시각으로 표시합니다. 인용문의 존재 여부는 코드에서 검사하며, 내용과 출처의 의미적 대응 정확성은 모델 품질에 달려 있습니다.

강의 삭제·이동으로 근거가 없어진 내용은 갱신 때 현재 본문에서 제외하고 과거 이력에서 확인할 수 있습니다. 출처 강의가 삭제되어도 이미 저장된 근거 인용문과 과거 기록은 종합 노트에 남습니다. 기존 방식으로 작성한 종합 노트는 다음 갱신 시 **ID 추적 이전 종합 노트**로 보존하며, 기록되지 않았던 과거 항목별 출처·추가 시각을 추정해 채우지 않습니다. 항목 ID·근거·변경 이력은 SQLite와 Markdown 다운로드에 모두 포함됩니다.

강의 최종 요약이 새로 완성·변경되거나, 관련 강의가 이동·삭제되면 과목 종합 노트에 **갱신 필요**를 표시합니다. 생성 중 자료가 바뀌면 오래된 결과를 최신 노트로 저장하지 않고 다시 갱신하도록 안내합니다. **기록 다운로드**는 현재 보고 있는 강의 노트 또는 과목 종합 노트를 Markdown으로 내보냅니다.

과목 폴더는 앱 안의 분류이며, 폴더·강의·종합 노트는 모두 같은 `data/notes.sqlite3`에 저장됩니다. 기존 DB에는 필요한 테이블과 열을 자동 추가합니다.

## 삭제

- 강의를 선택하고 **강의 노트 삭제**를 누르면 확인 후 해당 강의의 원문·실시간 요약·최종 노트를 함께 삭제합니다. 다른 강의는 유지됩니다.
- 과목의 **종합 노트 삭제**는 통합된 결과와 항목 ID·출처·변경 이력·추적 이전 본문을 모두 삭제하며 강의별 기록은 유지합니다.
- **빈 과목 폴더 삭제**는 강의가 없는 폴더에서만 가능합니다. 강의가 남아 있으면 먼저 이동하거나 삭제해야 합니다.
- 녹음·요약 중인 강의는 작업이 끝난 뒤 삭제·이동할 수 있습니다. 삭제한 강의 ID는 기록해 두어 늦은 저장 요청이나 이전 화면의 재시도가 노트를 다시 생성하지 못하게 합니다. 삭제는 복구할 수 없으므로 필요한 기록은 먼저 다운로드하세요.

## 요약 모델 선택

- **실시간 요약 노트**, **최종 노트**, **과목 종합 노트**의 선택 상자에서 각각 `gpt-6.1-sol`, `gpt-6-luna`를 고를 수 있습니다. 각 용도에 같은 모델을 선택해도 됩니다.
- 녹음 시작 시 두 선택을 고정합니다. 연결·녹음·요약·노트 불러오기 중에는 선택 상자를 잠그며, 실시간 재시도도 해당 녹음의 모델을 사용합니다.
- 마지막 선택은 브라우저에 저장해 다음 녹음에도 적용합니다. 최초 기본값은 `.env`의 `OPENAI_REALTIME_MODEL` / `OPENAI_FINAL_MODEL`입니다. 지원하지 않는 값이면 각각 GPT-6 Luna / GPT-6.1 Sol로 돌아갑니다. 과목 종합 노트의 기본값도 최종 노트와 같습니다.
- 이전 `.env`·브라우저 선택은 GPT-6 Sol → GPT-6.1 Sol, GPT-5.6 Sol → GPT-6.1 Sol, GPT-5.6 Luna → GPT-6 Luna, GPT-5.6 Terra → GPT-6.1 Sol로 연결합니다. 기존 노트와 변경 이력의 실제 생성 모델 표시는 그대로 보존합니다.
- 최종 노트가 이미 완성되어 있어도 다른 모델을 선택하면 **선택한 모델로 다시 작성** 버튼이 나타납니다. 클릭할 때 추가 요약 요청을 보내며, 성공하면 같은 노트의 최종 내용과 생성 모델을 갱신합니다. 실패하면 기존 완료 결과를 유지합니다.
- **생성 모델** 표시는 화면에 보이는 결과를 실제로 만든 모델입니다. 선택 상자만 바꿔도 기존 결과의 모델 표시가 바뀌지는 않습니다. 실시간 모델 변경은 다음 녹음에 적용되며, 기존 청크를 다시 요약하지 않습니다.
- 녹음별 모델 정보는 SQLite에 보관합니다. 기존 DB는 첫 접근 시 열을 추가하며 원문·요약을 보존합니다. 모델 정보가 없는 이전 기록은 생성 모델을 추정하지 않고 **모델 정보 없음**으로 표시합니다.

## 동작

```text
브라우저 마이크 (AudioWorklet → mono PCM s16le)
  → WebSocket /ws/session → FastAPI → Soniox
  ← 한국어·영어 원문 (확정 delta + 교체되는 임시 텍스트)

확정 원문의 <end> → 현재 청크 + 직전 최대 2개 청크 → 실시간 선택 모델 → 실시간 요약 노트
전체 확정 원문                                    → 최종 선택 모델 → 최종 노트
```

Soniox의 `enable_endpoint_detection: true`로 발화 경계를 받습니다. 확정된 원문 토큰을 응답 간에 모으다가 `<end>`가 오면 하나의 청크를 큐에 넣습니다. 한 응답에 여러 `<end>`가 있어도 각각 구분합니다. `<end>`는 고정 시간 간격이 아니라 Soniox가 판단한 발화 종료 지점입니다.

임시 토큰, 빈 청크, 중복된 빈 `<end>`는 요약 요청을 만들지 않습니다. 청크를 순서대로 한 번에 하나씩 요약하며, 각 요청의 `current_chunk`에는 현재 발화, `previous_chunks`에는 직전 최대 두 발화만 넣습니다. 누적 요약 전체를 매번 재전송하지 않습니다. 이전 발화는 문맥·중복 판단용이며, 새 사실과 반복, 뒤에서 정정한 내용을 구분하도록 지시합니다. 중복 판별 범위는 제공된 직전 두 청크입니다. 같은 요약 요청에서 현재 청크의 핵심 주제 제목도 생성하며, 제목을 위한 별도 API 호출은 없습니다. 요약 카드에는 번호 대신 이 제목을 표시하고 청크 번호는 보조 정보로 남깁니다. 각 청크의 원문은 SQLite와 다운로드에도 함께 보관합니다. 기존 기록에 청크별 원문이 없으면 임의로 경계를 추정하지 않고 저장된 요약만 표시합니다.

실시간 요약이 실패하면 같은 입력으로 2초 후 한 번 재시도합니다. 두 번 실패한 청크는 실패 상태를 표시하고 다음 청크로 넘어갑니다. 해당 원문은 최종 노트 입력에 남습니다. 연결이 끊기면 진행 중인 API 요청을 취소합니다.

종료 시 브라우저의 마지막 PCM 버퍼를 전송하고 Soniox에 **빈 텍스트 메시지 (`""`)**를 보냅니다. 빈 바이너리 오디오 프레임 (`b""`)은 종료 응답 없이 무시되는 현상이 실제 API에서 확인되어 사용하지 않습니다. `finished` 응답까지 받은 뒤 미완료 실시간 요약을 취소하고 전체 원문으로 최종 노트를 생성합니다. 대기 중인 청크와 마지막 `<end>`가 없는 발언도 최종 노트에 포함하므로 종료 시 요약 큐를 모두 처리할 때까지 기다리지 않습니다. 미완성 OpenAI 응답은 성공으로 처리하지 않습니다. 최종 노트가 실패하면 **최종 요약 다시 시도**로 재요청할 수 있습니다. 원문이 비어 있으면 요약을 호출하지 않습니다.

API 키는 서버에서만 사용하며 브라우저에 전달하지 않습니다. OpenAI Responses 요청에는 `store=False`를 지정합니다. 이는 앱에서 응답 저장을 요청하지 않는 설정이며, 제공업체의 데이터 처리 정책과는 별개입니다. 원본 오디오는 파일로 저장하지 않습니다.

## 범위와 제한

- 개인용 단일 사용자 MVP입니다. ngrok 실행 모드는 접속 비밀번호를 지원하지만 사용자별 노트 분리는 없습니다.
- 연결이 끊기면 확정된 원문과 완료된 노트를 저장하지만, 재접속으로 이전 녹음을 이어 붙이지 않습니다. 재시도 요약은 확정된 원문만 사용합니다.
- 기본 세션 제한은 2시간, 원문 제한은 20만 자입니다. 프로세스 강제 종료나 전원 장애 시 마지막 DB 저장 이후의 내용은 누락될 수 있습니다.
- 마이크 입력을 사용합니다. 파일 업로드, 시스템 오디오 캡처, 화자 구분은 이 MVP에 포함하지 않습니다.
- 마이크는 localhost 또는 HTTPS에서 동작합니다. 개인 휴대폰 접속에는 위의 ngrok 실행 모드를 사용합니다. 여러 사용자에게 서비스하는 운영용 배포는 별도 사용자 인증·사용량 제한이 필요합니다.
- 실시간 요약 지연은 발화 경계 감지, 대기 중인 청크 수, API 응답 시간에 따라 달라집니다. 기존 `SUMMARY_INTERVAL_SECONDS` 설정은 더 이상 사용하지 않습니다.

모의 Soniox/OpenAI 응답으로 언어·context 전달, 입력 제한, 확정 원문의 청크 경계, 여러 청크의 순서와 직전 두 청크 문맥, 재시도, 종료·연결 해제 시 요청 취소를 검증합니다. JavaScript 검증은 과목 저장·불러오기·삭제, 저장소 실패, 설정 잠금, 실시간 요약 제목·청크 원문 유지와 다운로드, 오디오 마지막 버퍼 전송을 확인합니다. 실제 혼합 언어 인식과 요약 품질, 계정별 모델 접근 가능 여부는 라이브 API로 별도 확인해야 합니다.

SQLite 검증은 임시 DB를 사용해 녹음별 세 결과 보관, 별도 Python 프로세스에서의 복원, 저장 실패와 연결 중단, 취소된 DB 쓰기의 순서, 재시도 전 최신 원문 저장을 확인합니다. 프런트엔드 검증에는 노트 전환·복원, 불러오기 실패 시 현재 내용 유지, 비동기 불러오기 중 동작 잠금도 포함합니다.

실제 브라우저에서 녹음 시작 → 종료 → 최종 노트 자동 완성을 확인하는 선택적 회귀 테스트도 있습니다. 가짜 마이크·모의 API·임시 DB를 사용하며 외부 API를 호출하지 않습니다. 실시간 요약 도중 종료, 느린 최종 응답, 모델 선택과 재작성, 서버 재시작과 새 브라우저 프로필에서의 복원, 과목 폴더 생성·강의 이동·삭제·과목 종합 노트 생성·갱신·삭제 및 모바일 화면을 검사합니다.

```bash
python -m pip install playwright
python -m playwright install chromium
python tests/browser_recording_check.py
```

위 명령은 프로젝트의 가상환경에서 실행합니다. Linux에서는 Chromium 실행에 필요한 시스템 라이브러리도 필요합니다.
